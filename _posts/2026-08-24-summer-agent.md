这个暑假的开始其实不算太顺利。大二下学期的时候，我主要在学 408 和数学一，后面又要准备学校的期末考试。本来的计划其实挺简单的，就是想在暑假找一份实习，但真正开始找的时候才发现，我好像并没有准备好。

当时手上没什么能拿得出手的项目，所以临时用 ChatGPT 做了一个刷题平台的测试项目，然后开始投测试开发的岗位。为什么是测试开发？其实原因也挺草率的，当时问 ChatGPT，它告诉我测试开发相对来说门槛可能低一点，于是我就去投了。

前前后后大概沟通了 80 个岗位，一个面试都没有。中间倒是有几个 HR 找我要了简历，然后也就没有然后了。最后还是老老实实回家了。

## 回家之后重新想方向

回家之后，我做的第一件事其实不是马上学什么，而是先看现在到底什么方向比较适合我。

Java 后端肯定是最容易想到的。岗位数量不少，技术体系也成熟，但问题就是学的人实在太多，感觉现在后端确实挺卷的。我之前学过 CS61B，所以 Java 本身不算完全没接触过，但如果真的要做到能找实习，差的东西其实还挺多。

Spring、MySQL、Redis、消息队列，以及后面一堆工程上的东西，都得慢慢补。

与此同时，我又开始注意到一些 AI 相关的岗位，比如 AI Agent、AI 应用开发、Agent 评测、AI Native，还有更偏模型一些的微调、RL 之类的方向。虽然这些岗位到底分别要求什么，当时我其实也没有完全搞清楚，但至少相比传统后端，它们看起来是一些正在快速发展的方向。

而且我本身是统计学专业，所以像模型评测、数据分析、微调、强化学习这些东西，至少表面上看也和自己的专业稍微有一点联系。于是当时我就在想，既然传统后端已经这么卷了，我是不是可以稍微往一些新一点的方向靠。

然后我就开始折腾 Agent。

## Agent 其实比我一开始想象得简单

刚开始看 Agent 的时候，感觉这个词还挺高级的。各种框架、Workflow、Memory、Tool Calling，看起来像是有一整套新的东西需要学习。

但学了一段时间之后，我的感觉反而是：应用层 Agent 本身其实没有想象中那么神秘。

LLM 可以理解成一个大脑，外面的 Agent Harness 更像是给它接上了手和眼睛。模型负责理解当前的任务、决定下一步做什么，外面的程序负责给它提供工具，让它能够读文件、跑代码、搜索东西，或者执行一些其他操作。

再简单一点，一个最基础的 Agent Loop，其实就是模型决定下一步做什么，调用工具，把结果丢回去，然后再让模型决定下一步，一直循环下去。从代码形式上看，最简单的版本甚至真的可能就是一个 `while`。

比如：
```python
messages = [{"role": "user", "content": task}]

while True:
    response = llm(messages)

    if response.tool_call:
        result = run_tool(response.tool_call)
        messages.append(response)
        messages.append({
            "role": "tool",
            "content": result
        })
    else:
        print(response.content)
        break
```

当然，这只是“能跑起来”。

真正开始做之后，就会发现很多麻烦的东西其实都在模型外面。比如上下文怎么管理，工具接口怎么设计，调用失败之后怎么办，怎么记录每一步执行过程，怎么防止 Agent 无限循环，怎么判断它到底做得好不好，以及一次任务到底花了多少 Token、多少时间、多少钱。

做着做着，我发现自己感兴趣的东西也开始慢慢从“怎么做一个 Agent”，转向 Agent 背后的这些工程问题。

后来再去看一些项目和岗位的时候，我发现这些问题其实已经比较接近 AI Infra 这个方向了。AI Infra 本身当然是一个很大的范围，模型训练、推理服务、数据、评测、Agent 基础设施这些都可以往里面算，我现在接触到的只是其中很小的一部分。

但至少目前相比于单纯做一个调用 API 的 AI 应用，我确实更想往 Agent、评测以及背后这些基础设施相关的问题继续了解。

## 这个暑假做的几个项目

最开始做的是 **AgentBenchOps**。

这个项目现在回头看，最大的问题就是东西塞得太多了。后端、Python、Agent、评测、各种功能，想到一个就往里面加一个。当时会有一种感觉：项目做得越大，功能越多，好像就越厉害。

结果就是后面越来越臃肿，而且真正问自己“这个项目到底解决了什么问题”，其实我自己都很难一句话说清楚。

所以现在再看 AgentBenchOps，我觉得它更像是我学习 Agent 过程中的一个大杂烩。很多东西都是第一次接触，看到什么觉得有意思就往里面加一点，最终确实做出了不少功能，但整体并没有一个特别清晰的核心。

当然也不能说完全没用。至少很多概念，比如 Agent 的执行轨迹、评测、任务运行、后端接口，以及一些工程上的东西，我都是在做这个项目的时候第一次真正碰到的。

后面因为开学之后要参加数学建模竞赛，我又开始做一个数学建模 Agent，叫 **Modellion**。

这个项目和 AgentBenchOps 不太一样，它至少来源于一个比较真实的需求。我是真的想看看 Agent 能不能在数学建模的过程中提供一些帮助，比如数据分析、建模思路、论文检索、代码执行，以及最后的论文写作。

现在的想法是从 Skill 开始做，把不同能力拆开，然后再慢慢把它们组合起来。目前还在开发，所以现在也不好说最后能做到什么程度。

再后来，因为越来越受不了 AgentBenchOps 那种什么都往里面塞的感觉，我又重新做了一个项目，叫 **Exagium**，主要是用来做 Coding Agent 评测的。

这个项目目前我自己觉得还是比较 toy。就是能跑，也有一些自己的想法，但如果真的把它叫做一个成熟的评测平台，肯定还差得很远。

不过这一次我开始刻意控制范围。

以前做项目总想什么都塞进去，现在慢慢开始觉得，一个项目真正重要的可能不是有多少功能，而是它到底想解决什么问题。如果连这个问题自己都说不清楚，那么功能再多，最后大概率也只是堆在一起。

这个变化对我来说还挺明显的。

## 后端还是得学

虽然现在比较想往 Agent 和 AI Infra 相关的方向走，但做得越多，反而越觉得后端绕不过去。

因为 Agent 最后还是得落到一个真实系统里面，总不能永远就是 Python 写一个脚本，然后本地跑一下。真要做成一个能够给别人使用的东西，还是会碰到数据库、缓存、并发、任务队列、鉴权、日志、部署、监控这些问题。

所以 Java 后端我还是想学。

之前也考虑过跟着苍穹外卖、黑马点评这些项目去做，但我自己看视频的效率好像比较低。看着看着就容易走神，而且很多时候是老师写什么我就跟着写什么，最后项目是跟着敲出来了，但真让我脱离视频再做一遍，可能就不太行。

所以后来我更多地选择用 ChatGPT 辅助学习。

目前也就是学了一些 Spring Boot、CRUD 这些比较基础的东西，Redis、SQL 这些还没有系统学。其实从现在做项目的情况来看，这些东西后面肯定都还是得补，只不过优先级怎么排，我现在也还没有完全想好。

除了 Java 之外，我个人现在其实也有点想学 Go。

为什么想学 Go，我也说不太清楚。可能一方面是语法看起来比较简单，另一方面就是我经常看到一些基础设施、云原生，以及现在一些 AI 相关的项目会用 Go，而且它在并发和网络服务这方面感觉比较舒服。

之前做 Agent 的时候，我基本默认就是 Python。毕竟 Python 写 AI 应用确实太方便了，各种 SDK、模型框架、数据处理的东西基本都有。

但如果以后真的去做一些 Agent 平台、后台服务，或者 AI Infra 相关的东西，我感觉 Go 也挺合适。

Java 当然也能做，而且生态肯定比 Go 成熟很多。只是从我目前看到的一些项目来看，我个人会更想了解 Go 一点。不过现在要学的东西已经不少，所以这件事暂时也只能先放着。

## 最大的问题可能是 Vibe Coding

其实这个暑假做了这么多东西之后，我现在最担心的反而不是“项目不够多”，而是项目做得太快了。

因为 AI 写代码真的太快了。

很多时候我只是描述一下我要什么，然后它很快就能给我写出一大段代码。再改一改，再告诉它这里有 Bug，那里要加功能，一个项目很快就能有个样子。

刚开始会觉得这个效率太爽了。以前可能一天才能写出来的东西，现在一两个小时就能有个初版。

但后面我逐渐发现一个问题：**AI 写代码的速度比我理解代码的速度快太多了。**

如果不停地让 AI 往前写，我根本来不及 Review。于是就会出现一种很奇怪的情况：项目确实是我做的，GitHub 仓库也是我的，需求也是我提的，功能也确实能跑，但如果突然有人问我这里为什么这么设计、这个类到底负责什么、这块为什么需要异步、数据为什么这样存，或者如果请求量突然变大之后系统会出现什么问题，我可能一下子答不上来。

这就挺尴尬的。

因为你说这个项目不是我做的吧，也不是。需求是我想的，架构很多时候也是我和 AI 一起讨论的，代码也是我一点点让它生成、修改出来的。

但你要说这些代码我全部掌握了，那肯定也没有。

我现在感觉，Vibe Coding 最大的问题可能就是很容易让人产生一种“我会了”的错觉。实际上很多时候只是“它跑起来了”。

而“跑起来”和“我理解它”完全是两件事。

尤其是以后如果真的拿这些项目去面试，这个问题肯定躲不过去。面试官不可能因为项目里有大量代码是 AI 帮忙写的，就不问其中的实现细节。

所以最近我也开始刻意去想，后面做项目的时候是不是应该稍微慢一点。AI 肯定还是会继续用，完全不用也没有必要，但至少核心模块得自己认真看，重要的代码得知道为什么这么写，有些地方甚至应该自己重新实现一遍。

不然最后 GitHub 上可能确实有好几个项目，但真正沉淀到自己身上的东西却没有多少。

## 写在最后

回头看这个暑假的前一段时间，其实和一开始设想的完全不一样。

最开始只是想找一份实习，没找到之后开始重新看方向；原本觉得自己可能会去补 Java 后端，后来又跑去研究 Agent，然后陆续做了 AgentBenchOps、Modellion 和 Exagium，中间又开始对 Go 和 AI Infra 这些东西产生兴趣。

整个过程其实挺乱的，也谈不上已经找到了什么明确的方向。

如果一定要说目前有什么变化，大概就是我开始从“为了找实习赶紧学一个技术”，慢慢变成了先去看看自己到底对哪些问题更感兴趣。

现在来看，我确实比较喜欢 Agent、评测，以及它们背后的一些工程问题。但到底之后会做到哪一步，会不会继续往这个方向走，我现在也说不好。毕竟现在接触到的东西还很浅，很多判断可能过一段时间再看，又会有变化。

这一篇就先写到这里吧。
